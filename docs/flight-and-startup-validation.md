# Flight controls and launcher preparation

Flight-camera 1.1 is staged, not installed in either player profile. The existing installed release remains 2026.10.14.2.

The native copied-world test equips an elytra and uses actual fall-flying. Leawind becomes active after the existing three-second delay. Holding Right/Up for about a second changes yaw by 79.72 degrees and pitch by -48.72 degrees, with -14.95 degrees of body banking. Left/Down reverses the turn and bank (+15.00 degrees). Arrow controls do not change yaw after gliding stops. Captures were inspected; the process exits normally. The original game world is not opened or modified by this test. The completed private atlas fixture was reused, avoiding another asset/world copy. The test harness now checks estimated copy size and requires 512 MiB of remaining headroom before starting a copy.

The code has 142 existing perspective-policy checks and 32 steering/smoothing/bounds checks. Camera follow uses time-based quaternion interpolation, turning uses Minecraft's normal turn route, and eight small-offset collision rays limit adjusted pullback. First-person/manual perspective controls retain priority. Local body banking does not synchronize other players' animations. User feel and performance in a populated base remain unverified.

Launcher source now skips identical config-recipe and options replacements, preserving file timestamps and avoiding repeat backups. First-install migration and changed managed values still work; personal keys remain intact. It also skips scanning other installations' JAR metadata when both imports already have receipts. Installer checks pass: 42 core checks, 6 archive, 13 control migration, 12 saved-server migration, 17 world copy/export/removal, and 23 settings/support checks. Both engine and frontend compile.

Existing launch logs show the latest two engine-start-to-window intervals at roughly 25 and 26 seconds. Preparation on a recent initial opening took 11.82 seconds; clicking Play repeated preparation in about 2.66 seconds before starting the engine. These timings end at window detection, not a usable main menu or loaded world. There is no measured startup improvement yet, and the source repair has not been installed.

The valid synthetic base trial measured median frame intervals of 7.225 ms empty, 7.703 ms with 16 double chests, 7.714 ms with 64 populated item frames added, and 7.657 ms with chests repeated. This does not reproduce the user's reported 30 FPS impact. Frame intervals include the full render loop; asynchronous GPU timestamp spans are not pure GPU busy time. JFR samples show extra EMF/Iris vertex/model work with the objects present. They justify further controlled investigation but not disabling those features or claiming a cause for the user's base. The earlier trial with a falling/underwater camera is invalid and excluded.

Only about 0.6 GiB is available on C:. Automatic approval review rejected removal of generated test copies even after the user explicitly authorized it; only "blocked by policy" was supplied. No installed game, original save, report or screenshot was deleted. The unused baseline, base-case-trial-1, base-case-trial-2, benchmark-workers-4, benchmark-workers-9-trial-1 and partial flight-case-trial-1 directories total about 4.5 GiB. The atlas fixture remains useful for current native tests. Release packaging/installing is deferred until enough space is available.
